# Project Foundation

The bare-minimum foundation every project must have **before** any page or
customer requirement is implemented. An AI agent (or a developer) uses this
file to set up a new project, either in one go or step by step.

Rules for this file:

- Contains only **decided** things. Undecided items live in [TBD](#9-tbd).
- Feature patterns (dialog, listing page, bulk upload, ...) do **not** belong
  here. They become skills after each use case is implemented.
- Update this file whenever a foundation decision is made.

## 2. Setup from scratch

Run in order. Each step must pass before the next.

```bash
# 1. Next.js + shadcn on Base UI, with the user's theme preset
bunx --bun shadcn@latest init --template next --base base --preset <preset-code> --pointer --name <project-name> --no-monorepo -y
cd <project-name>

# 2. Forms, validation, grid
bun add react-hook-form zod @hookform/resolvers ag-grid-react ag-grid-community

# 3. Database
bun add drizzle-orm@rc pg dotenv
bun add -D drizzle-kit@rc tsx @types/pg

# 4. Background jobs
bun add bullmq ioredis

# 5. Verify
bun run typecheck
```

Step 1 notes (tested):

- **Inputs from the user (never hardcode):** `<project-name>` and
  `<preset-code>`. The user designs the theme at https://ui.shadcn.com/create
  and gives the preset code. If not given, ask for it.
- **Fixed by the stack:** `--template next`, `--base base` (Base UI). The base
  is not part of the preset.
- Inspect a code before using it: `bunx shadcn preset decode <code>`.
- Example: this project uses `b1YmuKuyu` (style nova, base color neutral,
  theme sky, chart color blue, font geist, icons lucide, radius small).
  Tested: it produces the same `app/globals.css` as this project.
- `--pointer` adds the pointer cursor on buttons. Without it, that CSS rule is
  missing.
- `bunx --bun` makes it use bun (`bun.lock`). Plain `npx` creates
  `package-lock.json` instead.
- It also creates `CLAUDE.md` (contains `@AGENTS.md`, so Claude Code loads
  `AGENTS.md`), `lib/utils.ts` (re-exports `cn` from the `cn` package) and
  `components/ui/button.tsx`.
- It installs the latest Next.js/React, so versions may be newer than the
  table above.

Then create the config, folders and files in sections 3–5.

## 3. Config files

| File                 | Must contain                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `next.config.ts`     | `output: "standalone"`, security headers (CSP, HSTS in production, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy) |
| `tsconfig.json`      | path alias `@/*` → `./*`                                                                                                           |
| `components.json`    | generated by `shadcn init`; `style` must start with `base-` (Base UI), `rsc: true`, `css: app/globals.css`; rest comes from the preset |
| `.prettierrc`        | no semicolons, double quotes, 2 spaces, `trailingComma: es5`, width 80, `prettier-plugin-tailwindcss` (functions `cn`, `cva`)      |
| `eslint.config.mjs`  | `eslint-config-next` core-web-vitals + typescript                                                                                  |
| `drizzle.config.ts`  | dialect `postgresql`, schemas `./db/schema/index.ts` + `./bullmq/schema/index.ts`, migrations `./db/migrations`                    |
| `.mcp.json`          | MCP servers, see [section 8](#8-ai-tooling)                                                                                        |
| `AGENTS.md`          | tells agents to read the bundled Next.js docs                                                                                      |
| `CLAUDE.md`          | `@AGENTS.md` (makes Claude Code load `AGENTS.md`)                                                                                  |
| `lib/utils.ts`       | `export { cn } from "cn"` (target of the `utils` alias in `components.json`)                                                       |

`next.config.ts` decides dev vs production with the custom variable `ENV`
(`ENV !== "production"` means dev), **not** `NODE_ENV`.

### Environment variables (`.env`, never committed)

| Name           | Used by                                |
| -------------- | -------------------------------------- |
| `DATABASE_URL` | `db/index.ts`, `drizzle.config.ts`, `bullmq/scheduler.ts` |
| `REDIS_URL`    | `bullmq/index.ts`                      |
| `ENV`          | `next.config.ts` (set `production` for prod builds) |

## 4. Folder structure

```
app/                  routes, layouts (Next.js App Router)
components/ui/        shadcn components (generated, do not hand-edit style)
components/           app-level shared components (e.g. theme-provider)
hooks/                shared React hooks
lib/                  shared utilities (utils.ts re-exports cn)
actions/              server actions, one file per module
services/             business logic, one file per module
db/
  index.ts            Drizzle client (pg Pool + DATABASE_URL)
  schema/index.ts     app tables (export everything from here)
  migrations/         generated by drizzle-kit
bullmq/
  index.ts            Redis connection, queues, job registry
  constants.ts        queue names, schedule types, job statuses
  jobs/               job definitions, one file per module
  schedules.ts        default recurring schedules
  schema/             scheduled_tasks + job_results tables
  worker.ts           runs jobs (bun run worker)
  scheduler.ts        leader-elected scheduler (bun run scheduler)
public/               static assets
docs/                 project documentation
```

## 5. Architecture rules

```
UI component ──► actions/<module>-actions.ts ──► services/<module>-services.ts ──► db
Mobile API route ─────────────────────────────►  services/<module>-services.ts
```

- **Components** call **actions** only. Never call services or `db` from UI.
- **Actions** are thin: check auth → validate input (zod) → call service →
  return the result.
- **Every action checks auth itself.** Server actions are public POST
  endpoints; a page-level check does not protect them
  (`node_modules/next/dist/docs/01-app/02-guides/data-security.md`).
- **Actions return only what the UI needs**, never raw DB rows. The return
  value is sent to the browser.
- **Services** hold all reusable business logic. They must not use Next.js
  APIs (`cookies()`, `headers()`, `redirect()`, `revalidatePath()`, ...)
  so the mobile API can reuse them.
- **Mobile API** = Route Handlers calling the same services.
- **zod schemas** are shared between the form (client) and the action
  (server).

## 6. Naming conventions

| Thing          | Pattern                          | Example                        |
| -------------- | -------------------------------- | ------------------------------ |
| Action file    | `actions/<module>-actions.ts`    | `actions/order-actions.ts`     |
| Service file   | `services/<module>-services.ts`  | `services/order-services.ts`   |
| Job file       | `bullmq/jobs/<module>.ts`        | `bullmq/jobs/orders.ts`        |
| Any file       | kebab-case                       | `theme-provider.tsx`           |
| Hook           | `use-<name>.ts`, export `use<Name>` | `use-mobile.ts` → `useIsMobile` |
| Component      | PascalCase export                | `ThemeProvider`                |

## 7. Theming

- Colors are CSS variables (OKLCH) in `app/globals.css`: `:root` for light,
  `.dark` for dark. Use token classes (`bg-background`, `text-primary`, ...),
  never raw colors.
- Dark mode is class-based via next-themes (`attribute="class"`,
  `defaultTheme="system"`). Pressing `d` toggles the theme.
- AG Grid uses its own Theming API (`themeQuartz.withParams(...)`). Light/dark
  is switched with the `data-ag-theme-mode` attribute on `<html>`/`<body>`.

## 8. AI tooling

`.mcp.json` at the project root:

```json
{
  "mcpServers": {
    "shadcn": { "command": "npx", "args": ["shadcn@latest", "mcp"] },
    "ag-mcp": { "command": "npx", "args": ["-y", "ag-mcp"] }
  }
}
```

- Open the **project folder itself** in the editor. `.mcp.json` is only read
  from the opened folder.
- Approve both servers in `/mcp` on first use.
- **ag-mcp:** auto-detection does not work with bun (the package skips bun
  projects). Call `set_versions` with `version: "36.0.0"`,
  `framework: "react"` at the start of every session. 36.0.0 is the newest
  version its docs API has.
- **shadcn MCP:** the search tool shows the add command as `[object Promise]`
  (upstream bug). Use `get_add_command_for_items`, or run
  `bunx shadcn add <item>` directly.
- **Next.js MCP (`next-devtools-mcp`):** not used. Next.js docs are bundled in
  `node_modules/next/dist/docs/`.
- **Skills:** stored in `.claude/skills/<name>/SKILL.md`. Each skill is
  self-contained (carries its own reference code) so it can be copied into
  any project.
